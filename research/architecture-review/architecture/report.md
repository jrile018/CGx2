## Intended complete semantics

The design aims to let ordinary application data use traced managed storage while resources and explicitly controlled values use affine ownership and deterministic cleanup. Named regions have manual/auto policies, committed-byte limits and generative lifetimes. Collection in one region cannot invalidate another region's handle; cross-region movement/copying is explicit. Safe source must prevent use after move, invalid projections, conflicting loans, escaping borrows and double cleanup. Runtime validation complements these static rules. Ordinary managed values, aggregates, generic layouts and function results must participate in the same rules, rather than being omitted to fit an existing preview (A01, A11, A18).

`no_gc(budget: N)` excludes all CGx2 collection in the current single-threaded managed session, across regions. Every successful charged allocation participates in every active cumulative budget; nested scopes do not refund spend. An error does not undo earlier successful program mutations. Region limits and guard budgets are distinct. The contract is about CGx2-managed allocation/collection; it is not a bound on process RSS, execution latency, Python GC, LibTorch allocation or GPU synchronization. The 64-byte occupied-slot charge is logical runtime accounting (A06–A08, A14).

The complete source ownership deliverable requires fresh contextual aggregate construction, moved owned subcomponents, partial initialization and partial moves, disjoint projected loans, parent-aware reborrows, joins and loops, recursive call summaries, generics and package visibility/identity. Existing managed values cannot acquire owned identity by a contextual wrapper. Future explicit `copy_owned` and `promote` have separate contracts: independent tree copy with topology restrictions, versus consuming transfer whose failure carries the exact original affine owner. Raw managed graph copying must still preserve aliases and cycles. These operations must not be conflated (A13, A16–A18).

## Roots, regions, guards and failure observations

Runtime handles use session/region identity, slot and generation. Checked reads validate generation/occupancy; reclaimed slots advance generation, and saturated generations are not reused. That addresses one stale-handle mechanism but relies on all consumers using the checks. A bare unrooted runtime handle does not prevent region close; source escape checking and accurate root maps remain essential. Scoped roots own registrations and lexical checkpoints, so a root must be registered before collection can observe the temporary. Managed reference updates reject cross-region links; cross-region transfer must allocate or explicitly consume under its documented contract (A10–A13).

`ScopedRoots::with_no_gc` uses `try_no_gc`, moves registrations into a nested scope and handles unwind/restore. This connects source guard execution to a real lifetime mechanism. The compatibility `Session::no_gc` directly pushes its historical budget record and is a separate proof entry point. `check_budgets` compares every guard against `limit.saturating_sub(spent)`; `charge_budgets` increments spend after successful admission and saturates cumulative telemetry. Proving these operations requires the valid-state invariant, unchanged guards/bytes between check and charge, and machine-arithmetic bounds, not only a Nat calculation (A06–A08).

Rejection may increment region failure counters or fault diagnostics and may follow a temporary host reservation. The appropriate observation distinguishes payload/handle publication, successful charges, live roots/owners, primary errors and allowed diagnostic events. A blanket whole-runtime equality theorem is false for these observed rejection branches. Some counters use ordinary `+=`; reachable bounds or safe overflow behavior remain obligations even if telemetry is projected out of the semantic observation (A08).

## Concrete optimization and assurance seams

**Collector:** Let S be physical slots (including vacant slots), V reachable occupied objects, E reachable stored edge/reference positions, and P fixed-point passes. Current collection initializes S marks, repeatedly scans S plus the edges of marked objects, then sweeps S. A conservative bound is O(P(S+E)+S), with P ≤ V+1; reverse slot-order chains can require many passes. High-water slot length also matters when V is small. This is source-level algorithm analysis, not a measured runtime result (A09).

A worklist could give O(V+E) marking, while root discovery and sweeping still cost O(S). Alternatives have concrete tradeoffs: reserve O(V) external scratch with explicit failure/admission semantics; reuse preallocated session/region scratch with retained capacity and earlier charges; or add intrusive per-slot/object linkage/epochs, increasing metadata and introducing reset/overflow invariants. Each must preserve root/generation reachability, collection exclusion, cleanup and failure behavior. A new fallible reserve after marks change needs a defined failure observation; charging scratch can alter budget admission. Choosing an allocator, metadata format or collection policy is a substantive design decision. No redesign is selected or implemented here.

**Multiple routes:** Sharing a checked core/rooted evaluator could reduce duplicated profile dispatch, effect rules, source mapping and proof effort. It may require migration of established compatibility formats, larger universal invariants, and more complex common failures. Retaining bounded profiles can keep local reasoning small, but requires explicit profile relations and differential tests. Before choosing, inventory duplicated checks and demonstrate an actual inconsistency or cost. A04 authentication must not be mistaken for any of these preservation obligations.

**Ownership representation:** One authoritative tree/table limits drift between payload and drop maps, but detachment/ancestor metadata, bounded collection shapes, recursive summaries and source evaluation cleanup are substantial obligations. Replacing it with flat storage, intrusive structures or another ownership calculus would move these costs, not prove them away. The immediate gap is source connection and acceptance, not evidence of an impossible design.

**Foreign boundary:** Artifact hashes, environment grants and ABI version checks answer identity/authorization questions. They do not verify that a library honors allocation, aliasing, release, callback, thread or exception contracts. Strict protected source paths currently reject Foreign/Unknown/Collect transitively. Any narrower allowed foreign subset would need audited or verified semantics and enforcement across all profiles. Host Session guarantees do not extend to Python/LibTorch heaps, foreign threads, device buffers or asynchronous GPU streams (A14–A15).

**Formal boundary:** Existing `formal/memory-guarantees/NoGc.lean` is a standalone fixed-guard Nat reference model with 13 theorem declarations, historically reported kernel-checked. It omits guard entry/exit, Rust `usize`, actual capacities, fault injection, diagnostics, source lowering, root maps and foreign behavior. Its rejected-state equality does not describe the full runtime. The separate proof lane must report its own actual-source translation feasibility and trust chain; no model theorem or source anchor in this lane is implementation-connected evidence (A19).
