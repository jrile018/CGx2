## Functional equivalence and equipped policies

First compare identical successful values, checked arithmetic, input domains, shape/dtype/layout/device errors, error ordering, side effects and lifetime behavior. A signal, timeout, output overflow, wrong diagnostic or accidental test omission is a failure, never a successful negative. The independent oracle must not mirror one implementation's algorithm or trust its own test output. Freeze exact source/build/backend/test hashes. No timing starts until every compared route passes its full common functional/failure contract.

Run idiomatic and equally equipped implementations as separate strata. Idiomatic programs retain their ordinary allocator/collector; policy-only negatives are inapplicable and cannot earn guard guarantees. Equipped programs implement the same explicit policy heap/credit ledger, roots/handle checks, failure trace and foreign boundary. Report all wrapper/arena/collector/declaration/adapter code, documentation and implementation effort, plus all its execution cost. Rust without a tracing collector already avoids that collector's pauses. Python/OCaml can implement equivalent scoped policies with reviewed preallocation/arena/offheap designs where appropriate; do not assume intrinsic language limitations from missing fixture code.

The common logical credits in N03 are experimental representation-independent payload-policy units. They are not actual allocator bytes, RSS or CGx2 native `no_gc` budget bytes. Observe three columns separately: common logical-policy charges, native runtime capacity/metadata charges, and measured allocator/RSS/device memory. A claim of equal **native byte** admission needs a separately reviewed mapping that preserves every threshold/failure; do not silently tune each language's byte budget to reproduce outputs or normalize away CGx2 overhead. If exact requested byte contracts cannot match, mark the route incompatible/blocked and report the tradeoff before dependent timing. Logical-wrapper equivalence alone earns no claim of equivalent whole-runtime guarantees.

Rust may need no collector for an owned case and a reviewed tracing/arena abstraction for N02. Disabling Python cyclic GC does not stop reference counting, host allocation or all pauses. OCaml/Python arena policies scope their guarantees to that abstraction; ordinary host collector/runtime work is recorded and remains in end-to-end wall time. Do not pretend host allocations disappear because the experimental heap excludes them. Include equivalent root/error/lifetime discipline and any preallocation cost. No claim of universal pause freedom follows.

Cleanup observations distinguish payload/handle publication, ownership/root retention, successful cumulative charges, primary errors and allowed diagnostics. Earlier successful mutations/charges need not roll back. Avoid whole-state-equality assertions: failure counters, fault events and transient host reserves may change. Compatibility CGx2 `no_gc` and `try_no_gc` remain separate entry points. The initial managed-policy proof scope is one execution thread/session; owned worker transfers, shared managed heaps and asynchronous foreign/device work need separate contracts.

## Foreign and device fairness

Pin backend library/ABI/dependency closure, compiler/runtime builds, thread counts, tensor shape/dtype/layout, numerical flags and exact kernel graph. M01/M02 compare the same ATen compute through native facade versus explicit Python; include loading, wrapper validation, copies, transfers, synchronization, release and error translation. Standalone no-libpython evidence cannot be inherited by a CGx2 package. Wrong shape/dtype/layout must fail before the forbidden operation; no silent cast/copy/fallback changes the contract.

GPU paths must identify the actual discrete adapter and device allocations, execute the workload and synchronize before readback/timing. Record upload/download bytes, buffer aliasing, output ownership, allocated/reserved device memory, streams/queues and completion-lifetime rules. M04 compares one shader/backend across admitted bindings. It cannot be used as an ATen GPU substitute without a separately matched operation/numerical contract. Retain current PyTorch/LibTorch GPU blockers and driver caveat. Host Session/Lean results do not prove foreign threading, GPU buffer release or asynchronous failure atomicity.

Strict protected foreign calls require a justified explicit effect/memory/alias/release/callback/thread/error contract plus admission enforcement. An annotation/hash/grant alone does not prove behavior. This protocol excludes such calls from N03 unless a separately reviewed contract is delivered; ordinary foreign operations execute outside guards.

## Measurement and preregistration

After implementations pass independent correctness, stop setup/build contention and run pilots on a quiet pinned host. Pin CPU affinity/frequency policy, process/thread counts, toolchains, environment, input seed and repetitions; log actual pin failures. Measure cold process/import/load/compilation separately from warm calls. Include total end-to-end costs, with isolated kernel/collector phases as supplementary measurements. Count S/V/E, collector passes/edge inspections, copied bytes, allocation/failure events and logical charges independently from time. Keep all failed attempts and raw distributions.

Pilot noise/effect estimates determine practical thresholds, repetitions and power. Preregister them, exclusions, analysis and exact candidate identities before opening holdout data. Historical design targets are proposed targets, not calibrated results. Do not choose thresholds after results, infer p99 from tiny samples, compare unsynchronized GPU calls or time while tool setup competes for resources. Use repeated independent processes, confidence intervals and task/workload-clustered comparisons. Report native, ML and general results separately; no invented weighting or aggregate winner. Unsupported or contract-incompatible rows remain visible.

## Blinded correctness-first authoring study

Prepare 12 pilot and36 held-out task slots: bugfix, refactor and feature authoring equally represented; each family balances idiomatic/equipped policies. Each slot has equivalent four-language starter APIs, docs/dependency budgets, defect/requirement and independent sealed tests. Two model families with frozen versions are the minimum. Each pilot task/model/language receives2 independent repetitions (192 attempts); each holdout receives3 (864 attempts). This is a proposed study size, not a power claim; pilot-based power analysis may require a revised preregistration before holdout.

Pair by task/model-family/replicate, block by family/policy/difficulty, randomize language order with a recorded seed and counterbalance presentation. Separate authors/references/tests from trial workspaces. Exclude future git history, sibling solutions, hidden grading code, previous attempts and held-out failure feedback. Use clean independent sessions, equal public feedback/tool/context budgets and no synthetic observations. Assessors receive pseudonymous submissions and independent tests; syntax can reveal language, so report partial rather than impossible complete language blinding. Publish tasks only after retirement. Real human maintainability review requires independent participants and its own budget/consent process; self-ratings are not results.

Primary outcome is correct completion under the frozen acceptance contract. Per attempt cap:60,000 input tokens (including tool-result/context payload),12,000 output tokens and45 wall minutes including tools/tests. Record actual input/output/tool tokens, wall/tool time, repair turns, compiler/test failures and human intervention. Charge unsuccessful attempts their full **assigned** budget in all-task cost-to-success while preserving actual consumption separately; assigned failure cost is not fabricated actual API usage. Source tokens/bytes, readability and edits are secondary. Include failures in all-task analysis rather than reporting only successful pairs; provide paired uncertainty and completion-first comparisons.
