# Wave 14 candidate review and measurement packet

The two Wave 13 tasks remain **candidates**. `fixtures/task-candidates/v3/task-cards.json` is the reviewer card and checklist. Its review fields are intentionally null; an independent reviewer must record ambiguity, leakage, difficulty, corpus duplication, and an accept/reject rationale before any freeze. The card and `private/` are reviewer material and must not enter a model workspace or prompt. The model receives only the task statement and its selected starter tree. `pack.json` pins the starter snapshots, prompt and private harness hashes; `evidence-unrun.json` is an honest generated packet with no model trial.

## Acceptance boundary

Build `cgx2c` with `cargo build --offline -p cgx2c`, then run `python3 bench/fixtures/task-candidates/v3/private/accept.py` for reference and negative-starter smoke in both languages. For a submitted workspace, pass all of `--task`, `--language`, and `--candidate-workspace`; the path must be an external copy of exactly that task/language starter file set. The harness copies that path into a temporary build and never overlays the reference in candidate mode. Symlinks, special files, mixed language files, and source-level file/process/fixture access are rejected. The runner has a 90-second compile limit, 10-second execution limit, 64 MiB output-file limit, and 1 MB captured-output limit. A success is one integer line after CRLF and outer whitespace normalization; overflow requires nonzero exit and an overflow diagnostic. The arithmetic cases and group probes live only in `private/accept.py`.

The source restrictions are a task-specific guard, not a general sandbox against hostile code. This host disallows unprivileged bubblewrap namespaces. Run submitted code only in a separate isolated execution environment before using results as external evidence. The local smoke verifies reference/starter behavior and workspace binding, not model performance.

## Preregistered comparisons

Freeze reviewer-approved task cards, hidden harness, prompts, tools, model versions, dependency locks, hardware, and budgets before trials. Use the same task prompt and hidden acceptance across language conditions, randomized paired task order, repeated runs, and at least two independent model families. Select the strongest applicable baseline before observing model traces. The present candidates have reviewed starter conditions only for CGx2 and Rust. A human-written Python baseline needs an independently reviewed fixed-width i64 shim and equivalent hidden cases before Python enters a paired comparison; it is presently excluded in `pack.json`.

Record human authoring time for independently written CGx2, Rust, and eligible Python implementations separately from model latency. For each model trial record model family/version, prompt token budget, sampling settings, trial and run IDs, input/generated/total tokens, workspace digest, hidden pass/fail, latency, compile time, run time, and the paired baseline run ID. Charge failed trials their full consumed budget. Report output tokens and total tokens separately, plus first-pass and final hidden success. Report build/run success separately from runtime speed. Validate equivalent output before timing; use repeated independent process runs and intervals for latency and memory safety outcomes. Runtime speed and memory behavior are separate from authoring efficiency.

Compute task-paired differences within model family and language pair. Report the paired completion-rate difference with a 95% interval and predeclared noninferiority margin, plus paired medians and bootstrap 95% intervals for total tokens and latency on jointly successful tasks. Also report all-task cost-to-success to expose failed runs. Present family-specific results before any pooled estimate; do not select a favorable family or baseline after results. Record every exclusion, timeout, failed compile, and human intervention. The broader release-level target and required 60–100 task holdout are in `docs/validation-plan.md`; these two candidates alone cannot establish a language-level gain.

Generate or validate the packet with `python3 bench/candidate_packet.py --out PATH` and `python3 bench/candidate_packet.py --validate PATH`. An external JSON list can later be supplied with `--traces PATH`; the importer hashes that file and requires complete trace fields. It never executes a model, infers a performance improvement, or emits a benchmark win. Until independent review and paired traces exist, `run_state` is `unrun` and `claim_status` is `not_assessed`.

## Execution safety gate

The private `accept.py` CLI refuses `--candidate-workspace` by default. `--trusted-local-smoke` permits only coordinator-owned fixture checks on a trusted local host. It is an acknowledgement, not a sandbox. The command templates in `pack.json` deliberately omit this flag, so they cannot score submitted workspaces on this host. A future isolated worker must keep the private oracle outside the candidate process's filesystem and disable candidate network access before executing untrusted model output. Its isolation and scoring procedure require separate review; task cards remain unfrozen until then.
