# CGx2 pinned native binding preflight

`cgx2-bind check PACKAGE [--format text|json]` checks an explicit local binding package offline. Exit 0 means the declaration, target, artifact SHA-256 and exported symbol names passed; exit 1 reports diagnostics, and exit 2 is a usage error. It never calls `dlopen`, executes metadata exports, installs packages, resolves `.cg` imports, or falls back to Python. A matching symbol name cannot prove its physical C signature or the library's claimed version; the reviewed adapter checks runtime metadata before tensor calls.

The package uses `cgx2.toml` schema 2 with `binding_lock = "cgx2-bind.lock.json"`. The strict JSON lock has `schema_version: 1`, the package name, and nonempty bindings. Each binding pins `id`, `route`, `library`, exact numeric `version` (`major.minor.patch`), package-relative `artifact`, its exact 64-hex-digit `sha256`, host `os` and `arch`, `abi`, `calling_convention`, `layout`, and `symbols`. `render_lock` sorts bindings, symbols, effects and capabilities. The checker caps the lock at 1 MiB, an artifact at 256 MiB, all artifacts at 512 MiB, bindings at 32, symbols per binding at 128, and symbol inspection output at 8 MiB. Linux uses `nm -D --defined-only` without loading the artifact.

`native-c` retains the `c` ABI and `scalar-v1` or `status-i64-out-v1` layouts. The `libtorch` route is specifically the **CGx2 facade**, with `library: "cgx2.libtorch.cpu"`, `abi: "cgx2-libtorch-facade-v1"`, `calling_convention: "c"`, and `layout: "tensor-f64-cpu-v1"`. This facade is compiled against an exact LibTorch release through `torch/torch.h`; it is not LibTorch's stable C ABI. `version` is the exact asserted `Torch_VERSION`. The lock must name the built facade `.so` and its SHA-256, not a PyTorch wheel or general LibTorch library. `libtorch_facade_symbols()` returns the required nine exact declarations: identity, version, ABI, last error, create, add, length, copy and release. The C ABI returns status `i32` for tensor operations; create and add publish an owned handle through `handle_out_ptr`, and `cgx2_torch_release(handle_mut_ptr)` releases it. Tensor arguments are borrowed for a call. Creation copies `length * 8` input bytes into LibTorch-owned storage; copy writes exactly `length * 8` bytes to a caller-owned output buffer when capacity equals tensor length. No GPU or non-`float64` signature is accepted.

The preflight checks exact declarations and exported names, not C types or metadata *values* in the artifact. A caller must retain the checked artifact inode through native loading, as `checked_artifact` does, and use the reviewed `cgx2-libtorch` adapter for identity, version and ABI checks. `cgx2-bind` does not connect `.cg` source calls to this route yet.

Schema 1 keeps the historical facade-only preflight. Schema 2 retains the same binding fields and additionally requires `cgx2-libtorch-closure.lock.json` beside the package manifest for every `libtorch` binding. Its versioned entries pin the facade and every reachable ELF `DT_NEEDED` dependency by canonical absolute path, SHA-256, OS/architecture, and SONAME when present. `CGB019` reports a missing, extra, changed, noncanonical, or inconsistent closure entry, legacy `DT_RPATH`, or a `DT_RUNPATH` outside `$ORIGIN`. Preflight uses bounded `readelf -d` output and never loads the facade. The Linux adapter's `Torch::open_pinned` repeats preflight, checks already mapped SONAMEs, basenames, paths and inodes before `dlopen`, then checks actual `/proc/self/maps` identities after load and before tensor calls; static preflight alone does not prove loader identity. See `cgx2-libtorch/README.md` for the sidecar schema, bounds, and limitations.

Run `RUSTUP_TOOLCHAIN=1.98.1 cargo test -p cgx2-bind --offline` for the compiled C mock and adversarial preflight tests. `fixtures/libtorch-unavailable` demonstrates an otherwise well-formed declaration whose artifact is absent. The mock proves the binding contract shape and static checks; it is not evidence of real LibTorch behavior.

Wave 16 closure audit: `VerifiedClosure::verify_preloaded` and `verify_loaded` reject deleted executable mappings and compare the mapped device/inode of arbitrary executable filenames with their current path before using ELF SONAME inspection. This prevents a replaced on-disk file from describing an older loaded mapping. The check remains subject to races between inspection, `dlopen`, and foreign calls; matching hashes and declared symbols do not prove C ABI or native-code behavior.
