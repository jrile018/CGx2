# cgx2-ffi-native

Wave 10 host-side C ABI prototype. Supported host: **Linux x86-64**, Rust 1.98.1, a C11 compiler, and a shared library loaded with `dlopen`/`dlsym`. No Cargo dependencies or Python runtime are required. The crate does not expose `.cg` syntax or package binding commands.

`LibraryDeclaration::new(library_id, library_version)` defaults to `schema_version = 1`, `package_id = library_id`, `abi_version = 1`, `target_os = "linux"`, and `target_arch = "x86_64"`. Callers can set `package_id` separately. The loaded library must export `cgx2_library_identity() -> const char *`, `cgx2_library_version() -> const char *`, and `cgx2_abi_version() -> uint32_t`. Identity and version are exact strings, checked before any user function is called. This is a reviewed-library contract, not a way to authenticate arbitrary or hostile native code.

`Declaration::scalar(symbol)` supports exactly `int32_t fn(int64_t, int64_t *out)`; `Declaration::bytes(symbol)` supports exactly `int32_t fn(const uint8_t *, uint64_t, uint8_t *, uint64_t)`. Return status zero means success; any nonzero status becomes `Error::ForeignStatus`. The byte operation borrows the input only for the call and allocates one Rust output buffer for nonempty input. Its `CopyStats` reports the known host-side copy and allocation, not any allocation inside the foreign library. The output has exactly the input length; arbitrary growing or shrinking transforms need a future ABI shape. Encoding is bytes; callers may validate UTF-8 themselves.

`HandleDeclaration::new(create_symbol, read_symbol, release_symbol)` supports a fixed `int64_t` constructor/read operation and an owned opaque handle. All three symbols are resolved before creation. `OwnedHandle::release()` consumes the handle state only on status zero; on a nonzero status, the binding contract requires the handle to remain valid and owned so the caller can retry. A second call after success returns `AlreadyReleased`. `Drop` attempts to release an outstanding handle. If creation returns an error with a non-null handle, the adapter calls release before returning the error; cleanup failure there can still leak and requires a stronger future error contract. Handles and library instances are local to one thread (`Rc`, no `Send`/`Sync`), and callbacks are unsupported. The declared `foreign` effect is mandatory.

The declaration checks the schema, exact library identity/version, platform, supported C calling convention, operation shape, error channel, owner/release form, thread rule, and symbol existence. A C dynamic library cannot reveal a function's true signature or layout, so a false declaration for an existing symbol remains unsafe. `Library::open`, `bind`, `bind_handle`, and `symbol` are explicitly `unsafe` for reviewed facades; an identity/version string alone is not a signature proof. C++ exceptions and Rust panics must be caught inside a library-specific facade before crossing this C boundary.

Run `RUSTUP_TOOLCHAIN=1.98.1 cargo test -p cgx2-ffi-native --offline`. The integration tests compile a real C11 shared library with `cc` and exercise scalar/UTF-8 byte calls, error statuses, missing symbols, wrong version/platform/type/convention/owner, duplicate release, destructor on drop, and cleanup after partial creation failure. The current fixture has no callback, cross-thread, sanitizer, latency, or `.cg` source test.
