# CGx2 runtime kernel

This standalone crate is the first, safe Rust slice of CGx2 managed memory. It stores zero-initialized byte buffers with explicit same-region references. It is not connected to the compiler or a typed object layout yet. The crate uses no `unsafe` and no external dependencies.

## Public API

`Session::new() -> Session` creates a default auto region with a 64 MiB committed-byte limit and a 1 MiB trigger. `Session::default_region() -> RegionId` identifies it. `Session::create_region(mode: CollectionMode, limit_bytes: usize) -> Result<RegionId, AllocationError>` creates another region; modes are `Auto { trigger_bytes: usize }` and `Manual`.

`Session::alloc_bytes(region: RegionId, len: usize) -> Result<Handle, AllocationError>` creates a zero-filled buffer. `Session::read_bytes(handle: Handle) -> Result<&[u8], MemoryError>` borrows it. A handle is opaque and contains a region, slot, and generation; reclaimed or closed handles return `InvalidHandle`. Region and handle identities are session-specific. `Session::mode(region)`, `limit_bytes(region)`, and `stats(region)` return `Result<CollectionMode, MemoryError>`, `Result<usize, MemoryError>`, and `Result<RegionStats, MemoryError>` respectively.

`Session::root(handle)` and `unroot(handle)` return `Result<(), MemoryError>`. Roots are counted, so each successful `root` needs one `unroot`. `Session::link(parent, child) -> Result<(), MemoryError>` adds an idempotent same-region reference; a cross-region edge returns `CrossRegionEdge`. Edge storage can return `MemoryError::Allocation(AllocationError)`. `Session::collect(region) -> Result<(), MemoryError>` traces from roots and reclaims unreachable slots, including cycles. `Session::close_region(region) -> Result<(), MemoryError>` releases remaining storage when no roots remain; closing is not a collection. A handle left unrooted can be invalidated by collection or region close. The future compiler checker must enforce handle escape rules.

`Session::no_gc(budget_bytes: usize) -> NoGcGuard<'_>` borrows the session exclusively. The guard dereferences to `Session`, so it supports allocation, region creation, rooting, linking, and nested `no_gc` calls. Every successful allocation is charged to every active guard. An exhausted budget returns `AllocationError::BudgetExceeded` before commitment. Explicit `collect` returns `MemoryError::CollectionForbidden`, even for another region. Dropping a guard only removes its budget; it does not collect. An auto region that reached its trigger collects at its **next allocation safepoint after all guards exit**. A manual region collects only by explicit call.

## Memory report

`Session::memory_report() -> MemoryReport` snapshots all regions in creation order without collecting or mutating the session. Each `RegionReport` has its `RegionId`, open/closed state, mode (including the auto trigger), configured `limit_bytes`, `committed_bytes`, `live_bytes`, `peak_bytes`, `allocation_failures`, `collection_count`, `total_collected_bytes`, and `pause`. Closing a region keeps its row and terminal failure, collection, reclaimed-byte, peak, and pause counters; live and committed bytes become zero. Closed IDs are never reused. `MemoryReport::totals` sums the corresponding region counters with saturating arithmetic. Summed region peaks are **not** a simultaneous session peak.

`MemoryReport::to_json()` emits schema version 1 with stable keys and integer byte/nanosecond units. `to_text()` emits the same counters in a line-oriented format. No user-supplied names enter either rendering. The pause distribution has `sample_count`, `total_ns`, `min_ns`, `max_ns`, and 65 fixed log2 `buckets`. Bucket 0 counts zero nanoseconds; bucket *n* from 1 to 64 counts `[2^(n-1), 2^n)` nanoseconds, with the last bucket extending to `u64::MAX`. A duration above `u64::MAX` saturates for bucket/min/max selection; total nanoseconds use a saturating `u128`; sample and bucket counters saturate at `u64::MAX`. Empty distributions have zero min/max. Each completed collector call, including one with no live objects, adds one sample; rejected calls add none. Timings are wall-clock observations, so their values vary between runs. Histogram storage remains fixed per region and retains aggregate counts rather than individual samples.

The byte fields are logical CGx2 region charges, including reserved byte-buffer capacity, slot metadata, and edge capacity. They do not include region bookkeeping, owned buffers outside regions, host allocator overhead/RSS, Python/PyTorch memory, or device memory. `live_bytes` currently equals `committed_bytes` until collection or close because unreachable objects retain their charge until reclaimed. A later CLI can display a snapshot with `session.memory_report().to_text()` or `.to_json()`; this crate does not expose a CLI command.

## Unique owned buffers and transitions

`Session::alloc_owned_bytes(len: usize) -> Result<OwnedBytes, AllocationError>` returns a zero-filled, non-`Clone` buffer outside all managed regions. `OwnedBytes::len()`, `is_empty()`, `as_slice()`, and `as_mut_slice()` expose Rust borrows; dropping the value releases its storage deterministically. Rust ownership prevents implicit second owners. A compile-fail doc test checks that `Clone` is unavailable.

`Session::promote_owned(region: RegionId, value: OwnedBytes) -> Result<Handle, (AllocationError, OwnedBytes)>` moves the existing byte buffer into a managed slot without a payload copy. A failed region, budget, or host-capacity check returns the original buffer unchanged. The new handle starts unrooted, is bound to `region`, and follows the existing generation and collection rules. Promotion itself does not collect an auto region. `Session::copy_managed_to_owned(handle: Handle) -> Result<OwnedBytes, MemoryError>` copies the bytes into separate storage; it never steals the managed object or invalidates the handle. Stale handles return `InvalidHandle`, and an allocation failure is wrapped in `MemoryError::Allocation`.

## Accounting and scope

The logical charge for a byte object is its reserved byte-buffer capacity plus `SLOT_METADATA_BYTES` (64). A link charges newly retained edge capacity times `EDGE_METADATA_BYTES` (`size_of::<Handle>()`) to its region; when growth allocates a replacement edge buffer inside a guard, the full new buffer capacity is charged to every active budget. A region created inside a guard charges `REGION_METADATA_BYTES` (128) to active guard budgets, but region bookkeeping is not charged to that region's limit. Each allocation checks the region limit and every guard before commitment; failure increments the affected region's `allocation_failures` when a region exists. `RegionStats` exposes `committed_bytes`, `live_bytes`, `peak_bytes`, `allocation_failures`, `collection_count`, and `total_collected_bytes`. Here, live and committed are equal while objects remain allocated, including unreachable objects awaiting collection. The counters exclude foreign/Python allocations.

An owned allocation or managed-to-owned copy charges its actual reserved byte capacity plus `OWNED_METADATA_BYTES` (32) to every active `no_gc` guard. Owned storage has no region charge or per-region failure counter. Promotion transfers that same payload; it charges only `SLOT_METADATA_BYTES` to active guards because the payload was already allocated, while the destination region receives a charge of the payload's reserved capacity plus `SLOT_METADATA_BYTES`. The owned header charge is not transferred to the region. Region and budget checks precede commitment; a failed promotion increments the destination region's `allocation_failures` when the region is valid, with no change to committed/live bytes or collection count. All charges are cumulative within a guard, including allocations whose values are later dropped. These are logical charges rather than RSS measurements.

This kernel verifies its tested behavior for byte buffers and explicit edges only. It does not implement CGx2 source-level ownership/borrow or escape checking, automatic trace metadata for generated records, foreign handles or foreign memory accounting, concurrent collection, or a proof of memory safety for all future CGx2 programs. The conformance tests assert zero collection counts inside every guard case and include deterministic graph operations, stale-handle reuse, cycle reclamation, failure paths, region isolation, owned transitions, and nonaliasing copies.

Run `cargo test -p cgx2-runtime --offline`, `RUSTUP_TOOLCHAIN=1.98.1 cargo fmt --all --check`, and `RUSTUP_TOOLCHAIN=1.98.1 cargo clippy -p cgx2-runtime --all-targets --offline -- -D warnings` from the repository root.

The Wave 9 memory audit adds a 2,000-seed fixed and 10,000-seed extended direct-runtime corpus in `../cgx2-memory-conformance/`, plus regression tests for nested guard unwinding and region close followed by creation of a new region. Every v4 operation compares public results and deterministic counters with an independent model. The corpus found no runtime defect, so the public `Session` API, collection modes, `no_gc` accounting, and report schema are unchanged. See `../cgx2-memory-conformance/audit-v4.json` for operation and error counts, skipped steps, timings, and open hard gates. These finite byte-object tests do not establish thread safety, arbitrary typed layout safety, or foreign memory coverage.
