## Required executable source behavior

1. **General aggregate ownership.** Support concrete generic records and variants, `List`, `Array`, UTF-8 `String`, and nested ownership-bearing `Result`/`Option` combinations. Support affine values in function parameters/results and aggregate fields where the ownership type rules permit them. A sum's active arm may own multiple nested components; do not encode every sum as the old single Ok owner with an owner-free Err. Ordinary user construction and matching of legal ownership-bearing aggregates must work, with exactly-once component moves and cleanup. Compiler-only allocation errors and capabilities remain unforgeable.
2. **Usable construction before B.** Generalize existing `owned(EXPR)` and `try_owned(EXPR)` to the required freshly constructed aggregate forms, including nested aggregate construction and moved owned components. Preserve source evaluation order and existing scalar-record semantics. The new contract must specify contextual owned construction and the distinct handling of copied scalars, fresh constructors, moved owners, and function results. It must not silently deep-copy or steal an already managed aggregate: conversion of existing managed values remains explicit B work. This distinction must not leave any required owned aggregate without an executable source construction path. `try_owned` recovery must release already consumed temporaries exactly once and preserve the primary error; it does not promise B's same-owner recovery.
3. **Places and partial moves.** Support nested field and statically known index projections, disjoint projected borrows, projected reads/writes, partial moves and destruction of only the initialized remainder. Preserve whole-place invalidation and overlap checks. Dynamic indices use conservative overlap; unsupported dynamic owned moves reject before execution. Empty and out-of-bounds collections retain defined checked behavior, never unchecked storage access. A String is valid UTF-8; partial byte moves or mutations must not manufacture invalid text.
4. **Loans and reborrows.** Shared and exclusive loans retain exact base storage and projection provenance through calls, generics, packages and matching. Reborrowing must track its parent; exclusive parent access is suspended while a child loan conflicts and resumes only when allowed. End call-only loans at the actual call boundary unless a valid returned loan extends them. Returned loans must derive from eligible surviving borrowed inputs, never local owners, consumed inputs or dead regions. Do not end/recreate a loan token to evade alias checks.
5. **Control flow and recursion.** Support branches, matches, joins, early returns, existing loop forms, zero-trip paths, repeated slot initialization and recursive/mutually recursive ownership calls. Join definite initialization/liveness by intersection and possible state/origins by union, preserving discriminant refinement and partial-move state. Check contracts and failed argument evaluation against the real evaluation order. Recursion requires body validation over a bounded SCC fixed point, not a self-authenticating list of assumed summaries. Module import cycles retain their existing rejection; function recursion is a separate requirement.
6. **Generics and packages.** Preserve ordinary constraint/substitution/inference rules and qualified nominal identities. Validate generic ownership relations at declaration checking and concrete layout/loan/region substitutions at specialization. Include unused generic declarations and private/unused bodies; reachable-main specialization must not hide a malformed declaration or dishonest ownership/effect contract. Recheck every explicit transitive package dependency and public/private visibility. Named and positional calls retain existing language behavior and evaluation order.
7. **Mixed execution.** Owned, managed, regions and guards share the one actual execution Session. Preserve lexical generative brands, normalized `memory.Value` qualifiers, invariant Ref writes, managed graph closure and authenticated region substitutions. Traced managed aggregates cannot hide an owner, loan or affine capability. A owns the checking of these distinctions; no implicit transfer is introduced. Preserve pre-Session scalar fallback, the prohibition on entry contracts there, and existing runtime primary error identities.
8. **Runtime effects and cleanup.** Infer and authenticate allocation/resource effects and behavioral effects/capabilities separately through the complete call graph. Unknown is not false. Preserve existing effect requirements for owned allocation and contract evaluation. All active guards include actual successful owned payload/metadata/root/guard charges across regions; cleanup never refunds charges. No collection occurs under `no_gc`, and Manual exit/failure never collects. Scope/return/error cleanup releases actual initialized storage and roots, including partially built aggregates, moved arguments and reborrow temporaries, in documented lifetime order.

Do not postpone one of the above families into B. B is conversion semantics, not a second opportunity to finish basic ownership, recursion, packages or source attribution. Existing deliberate topology restrictions on mutable/cyclic Ref-bearing ownership must be stated precisely, tied to the original remaining ledger, and tested; they cannot be used to reject the required ordinary immutable aggregate family.

### Frozen source construction and projection rules

Use existing `owned(EXPR)`, `try_owned(EXPR)`, dotted name paths, bracket indexing, `borrow(PLACE)` and `borrow_mut(PLACE)` grammar. No new move keyword, postfix dereference syntax or source lifetime annotation is required. Builtin selection follows resolved identities, with the accepted user function/nominal precedence; spelling alone is not authority. The following is the source contract to implement, not a proposal left for a later producer.

- An unshadowed `owned(EXPR)` checks EXPR in an owned-construction context and yields `owned<T>`; `try_owned(EXPR)` uses the same context and yields allocation-free `Result<owned<T>, AllocationError>`. The context applies recursively to fresh record/variant/Option/Result constructors, list literals, String literals and the resolved `array([…])` constructor. Construction does not first build a managed graph and then invoke an implicit conversion. Bounds and charges precede each storage commitment. Existing copied-scalar/scalar-record input behavior is preserved.
- A copied scalar leaf is evaluated once and copied. An existing owned component is moved once into its destination component, preserving its storage identity. A nested fresh aggregate receives owned storage directly. Function calls keep their declared result/storage semantics: copied scalar results and owned results may supply components, but a call returning an existing managed aggregate cannot be rebranded. No ambient owned context changes a callee's allocation behavior. `owned(existing_managed)` and a managed aggregate embedded as a leaf reject; the later explicit `memory.copy_owned` is the conversion route. Ordinary unannotated aggregate construction outside this context remains on the existing managed route; old scalar-owned compatibility behavior is unchanged.
- A non-copied subtree of `owned<T>` projected in consuming position yields its owned subtree and invalidates exactly that place. An explicitly `owned<U>` field transfers its existing owner without adding a second owned wrapper. Reading a copied scalar field/index copies it. `let moved = owner.left`, `consume(owner.left)` and `let moved = items[0]` are move positions; `borrow(owner.left)` is a loan position. A whole partially moved aggregate cannot subsequently be read, moved or borrowed; disjoint initialized components remain usable and the remainder is destroyed automatically.
- Static index moves use nonnegative integer literal indices in existing bracket syntax, including chained indices. Dotted fields may precede brackets (`tree.items[0]`). All admitted indices are checked against runtime collection length before accessing or moving a component. No constant folding of arbitrary expressions is required to authorize a move; `items[i]` is dynamic even when an optimizer could infer i. Dynamic reads/loans use checked bounds and conservative overlap; dynamic owner moves reject. `get` retains its established copied/managed behavior and is not a hidden move operation. An in-type literal index outside the runtime length is an admitted program with an owned runtime bounds failure (`CGR080`, message `owned index out of bounds`, span of the complete indexing expression), not a successful static-negative fixture. Check bounds before detachment or loan creation; the indexed source owner is unchanged by the failed projection until ordinary error cleanup runs. `try_owned` catches AllocationError only and cannot disguise this bounds error as allocation recovery. This owned-place projection rule does not change copied/managed indexing's existing Option semantics.
- The current parser does not support field postfixes after brackets or indexed assignment. Use `let item = borrow_mut(items[0])` followed by `item.value = 3`, or move the element to a named owner first. Nested dotted assignments through a named exclusive loan use the existing assignment path. A scalar loan's value is read through its named loan binding; assignment to that exclusive scalar loan writes its referent and does not rebind the loan. This permits `let cell = borrow_mut(numbers[0])` followed on its own line by `cell = 3` using existing name assignment grammar. An immutable loan binding still cannot be rebound or assigned another loan/owner; only the exclusive referent is mutable, as with existing `p.field = value` for an exclusive parameter. Shared scalar loan assignment rejects. Bare `items[0] = 3` is not needed to meet this projection contract. Parser changes adding public exhaustive AST variants are not authorized as a shortcut.
- `borrow(loan_or_owned_place)` produces a shared projected child loan; `borrow_mut(exclusive_loan_or_owned_place)` produces an exclusive child loan. Applying `borrow_mut` to a shared loan rejects. A named child ends at lexical scope exit; inline argument children end after the call unless the checked returned loan extends them. Shared reborrows suspend conflicting parent writes; exclusive children suspend conflicting parent reads and writes. Reborrowing may never revive a consumed owner or change storage identity. A returned projected child is valid only under its body-derived borrowed-input provenance.

Reading a named scalar loan in a copied-scalar context copies its referent; passing or returning it in a `shared<T>`/`exclusive<T>` context preserves loan identity and provenance. Exclusive forwarding obeys the same reborrow/lifetime rules; it never creates an independent exclusive alias. Shared scalar assignment always rejects, and ordinary immutable scalar bindings retain their existing assignment prohibition. Type-directed referent access is specific to checked loan values and does not reinterpret ordinary bindings.
