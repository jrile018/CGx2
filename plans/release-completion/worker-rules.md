# Common worker rules

1. Work only in the Git worktree attached to your chat, on a `riley/` branch. Never edit the original checkout. Before coding read local AGENTS.md, docs/language-design.md, docs/validation-plan.md, plans/roadmap.md, plans/wave28/README.md and REVIEW.md, this directory's README.md/contracts.md, and your assigned plan.md.
2. MegaMemory overview at session start, query before project understanding, record precise implemented APIs/limits/paths after delivery. Read Serena initial instructions before coding.
3. Exclusive write ownership is the exact path list in your plan. All other tracks, root Cargo.toml/Cargo.lock, shared specification/roadmap/progress/coordinator ledgers are read-only. Owned Cargo.toml changes are allowed with already available or std-only dependencies; discard generated root lock edits before committing and report dependency additions for coordinator reconciliation.
4. Preserve frozen existing interfaces. New APIs must be additive/versioned. If a necessary shared change is discovered, describe the exact contract/change and finish useful owned work; do not edit another track or silently narrow your acceptance.
5. Finish one coherent deliverable, run specified checks, write an owned evidence report, commit code and evidence, report commit/files/results/limits, and stop for user review. Do not merge, create other chats, delegate, contact people, launch a follow-on task or edit coordinator plans.
6. Use private `CARGO_TARGET_DIR=$PWD/target/release-LANE`, `TMPDIR=$PWD/target/tmp-LANE`, logs, generated fixtures and ports; create these directories before use. Set `CARGO_BUILD_JOBS=2` to avoid 12 chats overwhelming the host. Use `RUSTUP_TOOLCHAIN=1.98.1`; if required and still present use `LIBRARY_PATH=/tmp/cgx2-wave22-lib`. Never share the original checkout's Cargo target. Release timing waits for a quiet host.
7. Run owned offline package tests/all-feature Clippy/all-targets `-D warnings`, owned formatting and git diff checks. Read-only consumer checks are allowed in your private target. No need for every chat to rebuild the full workspace. New crates are discovered by existing `members=["crates/*"]`; root manifest is not yours.
8. Local loopback tests may require sandbox escalation. Missing runtime/solver/GPU/isolation/registry artifacts yield explicit blocked/unrun acceptance with runnable instructions, not mocks relabeled as real evidence. No package installation or host security changes are authorized merely by this plan.
9. Do not spend on external model APIs, send messages or recruit participants. Produce operator-ready commands and input requirements for actual studies.
10. Record source-level versus library-only support, real versus fixture evidence and every remaining dependency. Preserve historical results and existing native/Python route separation.
