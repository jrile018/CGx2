# Checked effect and capability summaries across package imports

**Goal.** A checked local package should accept an explicitly pure wrapper around a proven pure imported function and enforce real transitive effects/capabilities through imported calls, instead of labeling every qualified call `Unknown`.

**Exclusive ownership.** `crates/cgx2-sema/**`, `crates/cgx2-package/**`, `crates/cgx2-api-index/**`, `crates/cgx2-cli/**`, `crates/cgx2-emit-rust/**`, `crates/cgx2-emit-python/**`, `crates/cgx2c/**`. No notebook, syntax, runtime/ownership/memory-conformance, verifier/effect-index/security, foreign/binding, bench, root Cargo or shared-document edits. Preserve current syntax and scalar/record/runtime profiles. Additive imported metadata/checking helpers are allowed; keep existing call signatures and conservative defaults available to frozen consumers.

## Checked summary contract

1. Extend the existing checked local-package graph pipeline to derive effects and required capabilities from verified function bodies, local calls and already checked dependency modules in dependency-first order. Module cycles, missing/unlisted imports and visibility/type failures still reject at the existing boundary. Local recursive effect inference retains its bounded fixed-point behavior. A module or body that fails checking must not publish a trusted summary to callers. Never equate a missing summary, a spelling match or an empty annotation with purity.
2. Associate imported summaries with fully resolved defining-module/function identities and the checked snapshot. Only an explicitly imported public function can use that summary. Private, undeclared, unresolved or out-of-context calls retain diagnostics/Unknown; constructors remain distinct from function calls and argument effects must still be visited. Preserve Unicode, qualified-name collision handling and public nominal-record identity. Single-source unnamed packages and existing standalone checking remain supported.
3. Propagate all existing effect/capability categories without dropping Unknown, ReadArgs/ArgsRead, Foreign or native capability distinctions, allocation/collection/mutation effects, or transitive local helpers. Gather calls in arguments, branches and range bodies/endpoints even when inactive/empty. Existing no_gc, unsafe binding, declared effect/capability and target admission rules remain authoritative. Body-derived inference and declared public upper bounds/statuses must retain their current local semantics; do not silently weaken a declared boundary or reinterpret capabilities while adding imported resolution.
4. Explicit `effects()`/`caps()` wrappers around checked pure imported scalar/record functions must pass. Wrappers whose dependencies require effects/capabilities must reject missing declarations at the caller source span with useful target context, and pass when valid under existing rules. A dishonest empty declaration in a dependency rejects before any caller is considered safe. Unknown stays conservative when only signatures are available: default `ImportedSignatures` without verified imported summaries cannot authorize purity. Add metadata with defaults rather than forcing notebook or other consumers to fabricate summaries.
5. Public package/API-index output must reflect the checked transitive summaries and existing declared-versus-inferred statuses. Preserve fresh-check equality in `build_index_with_imports`; mismatched typed/source/import metadata must fail, not reuse stale indexes. Keep deterministic order and source/related locations. `verify_unchanged()` and canonical/source/manifest checks remain in force after source edits. Do not add a globally cached summary detached from the package snapshot or a source-text annotation shortcut.

## Consumer and scope boundary

6. Exercise existing package check/run/native debug/release/Rust/Python paths for supported pure wrappers and record APIs. If a consumer rechecks/lower-flattens package code, preserve summary consistency and rejection behavior. Precisely inferred effects must not accidentally admit unsupported package memory, foreign calls, mutable records or new runtime routes. Qualified calls in contracts or special pure-only contexts must keep their existing admission rules unless equivalent trusted termination/purity evidence is already available; resolving an effect set alone is not a new contract proof. Do not broaden the verifier.
7. Notebook and standalone advisory effect/security tools are read-only consumers in this lane. Notebook pure package behavior must remain compatible; new checked wrappers should work through its existing lowering, while effectful imports remain rejected. Advisory tools without checked package context may still report Unknown: document this distinction instead of globally treating qualified names as trusted. No change to local-mutation classification is part of this lane; notebook work relies on the current `Mutate` category.

Use actual checked package fixtures, not only fabricated empty summary maps. Compare supported interpreter/native debug/release/Rust/Python outputs and errors, including atomic output preservation on rejection. Run owned offline suites, formatting and owned all-target/all-feature Clippy `-D warnings`; run notebook and advisory regressions read-only. Commit implementation, readable package examples and an owned report with exact commands/results/limits; record knowledge, report commit and stop for review.
