# Notebook-local integer accumulators and bounded range loops

**Goal.** Notebook-defined computational functions can perform deterministic repeated work using local mutable i64 accumulators and statically bounded ranges, while retaining dependency tracking, transactional publication and existing replay/resource limits.

**Exclusive ownership.** All five `crates/cgx2-notebook-*` crates, including examples/tests/evidence. No syntax, sema/package/API-index, CLI/compiler/emitters, runtime/ownership, verifier/effect-index/security/foreign, bench, root Cargo or shared-document edits. Consume frozen AST, checker, interpreter, worker and value interfaces. This lane must pass independently of concurrent package-effect changes.

## Admitted local computation

1. Extend only notebook-defined function bodies. Admit `let mut` i64 locals and existing simple/compound assignment forms to those locals, with checked arithmetic/type rules. Assignment targets must resolve to a mutable scalar declared in that function and currently in lexical scope. Reject writes to parameters, loop indices, captured retained bindings, imported/module names, records/fields, globals or outer notebook cells. Nested if/loop bodies may update an enclosing function-local accumulator. Block locals must not escape; preserve existing shadowing and lexical name resolution instead of using a flat set that misclassifies captures.
2. Admit existing ascending half-open `for i in range(start, end)` only when both endpoints are signed in-range i64 literals and there are exactly two positional arguments. No parameter/index-derived endpoints, arithmetic/calls in endpoints, arbitrary iterators, steps, break/return within loops or index mutation. Evaluate with existing source semantics; start >= end is empty. Nested loops and if statements are supported. Loop indices are immutable i64 and scoped. Use existing scalar checker for numeric/scope behavior and ensure notebook facts/preflight agree.
3. Existing semantic analysis labels assignment `Mutate`. Admit that category only for notebook-defined functions whose complete bodies are independently checked to perform the function-local mutation above. Accept explicit `effects(Mutate)` or inferred local Mutate; reject extra effects, capabilities, foreign/memory/no_gc/contract operations, unsupported statements and hidden effectful calls. An explicitly empty annotation on a mutating body remains a checker error. Do not relabel arbitrary Mutate as pure or authorize effectful replay. For a call outside a loop, an admitted local computational callee may carry this same proven local-only mutation; validate every callee body and reject recursion as before. Inside range bodies retain the frozen checker’s pure-helper-only call rule; a mutating helper cannot be smuggled through a wrapper.
4. Imported package functions retain the existing Wave 27 notebook profile: no mutable/loop bodies or nonempty declared effects are newly admitted. They may supply proven pure scalar/record helpers to local loops after existing closure lowering. Do not depend on new imported summary APIs. Public records can be read/projected as before, but only i64 locals are mutable and record values/fields remain immutable. Top-level notebook cells remain immutable bindings/expressions or definition/import cells; no top-level loop or mutation support is added.

## Static resource and replay contract

5. Extend the conservative static cost estimator before execution/replay. Count range setup, each executed iteration/body/assignment/expression, nested calls and both conditional branches conservatively; multiply literal trip counts and nested costs using checked/wide/saturating arithmetic so i64 MIN/MAX cannot wrap into a cheap estimate. Preserve the **100,000 static step limit**, **32 call-depth/function limits**, **1 MiB replay/state limits**, and existing worker frame/deadline limits. Oversized work must reject before publishing definitions/values or spawning a worker. Do not remove the static bound and rely only on timeout or the interpreter's larger runtime step cap. Zero-trip bodies are still statically checked for forbidden operations and dependencies, even though their execution cost is zero. The estimator must bound actual generated invocation/replay overhead as well as visible loop statements.
6. Update all function statement/expression walkers: admission, call discovery, external reads, annotation dependencies, scalar/record type validation, static cost, effect classification and source handling. In particular `collect_call_names_statement`, `collect_function_block` and `statement_cost` must recurse loops; assignment RHS calls and identifiers must be tracked. Local assignment targets/indices are not notebook dependencies. Reads/calls in inactive branches and empty loops remain dependencies so edits invalidate all affected readers. Do not allow a loop to hide an imported effect or an unresolved function.
7. Execute through the existing checked interpreter and tagged worker; no second evaluator or source unrolling. A local accumulator exists only for one invocation; failed/overflowing/cancelled calls cannot publish partial retained values or change earlier cells. Preserve first source-span diagnostics, worker type/record validation, retained definition invalidation, save/reopen semantics and nominal identities. Reruns and sweeps recompute locals from initializers; neither a cached accumulator nor hidden external state may survive invocation boundaries.
8. Cover selected/affected rerun, Restart and Run All, clean sweep, save/reopen/export and loopback UI with a readable notebook using local sums/nested bounded loops and a pure imported helper. Explain that these functions are replay-safe local computation even though the compiler retains the Mutate annotation, and that externally effectful workflows remain unsupported.
