# CGx2 progress estimate after Wave 16 review

**91% of the first usable release implementation scope.** This is a judgment-based inventory estimate, not a benchmark score or a passed release gate. Memory correctness, full functional conformance, LLM value, and runtime value remain open release decisions. The OCaml-scale long-term platform goal remains below 10%: the standard library, ecosystem, debugger, language server, mature compiler, and compatibility record are still missing.

| First-release area | Weight | Credit now | Evidence and largest gap |
| --- | ---: | ---: | --- |
| End-to-end safe memory | 30 | 29 | Wave 16 ran a 1,024-seed direct-runtime collection/cleanup corpus and targeted AddressSanitizer checks. Final-unwind report zeros still derive from source bindings rather than a runtime root census; foreign, concurrency, and other dynamic-tool evidence remain open. The memory release gate has not passed. |
| Core language and native toolchain | 20 | 19 | Native debug/release builds handle bounded local object graphs and operation/final-unwind failure snapshots. The snapshots need a runtime root census; typed object IR and broader function signatures remain open. |
| Modules and code understanding | 10 | 9 | Acyclic local imports and public scalar calls check and execute in a native package. Ecosystem dependency resolution and richer module APIs remain open. |
| Library access and source translation | 10 | 8 | A bounded unsafe `.cg` CPU float64 tensor call uses a pinned ELF closure without Python. Wave 16 strengthened module identity and handle checks; a worker reported a real LibTorch 2.14 CPU run with temporary pins, but independent reproduction, general tensor values, and broad library access remain open. |
| Native notebook | 10 | 9 | `.cgnb` has bounded restart/interrupt and conservative stale-output behavior. Effectful cells are explicitly rejected; pure user functions and broader Jupyter-scale execution remain open. |
| Effects, contracts, proof, security | 10 | 9 | The verifier records bounded solver observations and unsupported obligations while global proof remains `unknown`. No live Z3/CVC5 result or independently checked full proof has run. |
| LLM and runtime evidence | 10 | 8 | Scored candidates now require aggregate cgroup controls and fail closed when this host lacks delegated controllers. Coordinator review fixed closed-output-pipe timeout monitoring. Human task review, live isolated scoring, and paired model trials remain absent. |
| **Total** | **100** | **91** | Memory correctness and multiple first-release features still gate release. |

Credit reflects integrated, tested behavior on `wave16/integration`; it is not a fraction of elapsed time. Six Wave 16 worker commits were integrated and a benchmark timeout defect was fixed during review. A standalone component earns partial credit, while a language-level claim requires source-to-runtime evidence. The worker-reported LibTorch run is not reproducible from committed pins; a trusted solver result and model holdout remain unrun. The measured CPU choice covers one pure map primitive and machine, not arbitrary `.cg` code or GPU. The hard memory gate cannot be traded for speed or syntax brevity.
