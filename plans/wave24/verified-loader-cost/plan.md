# Reduce verified loader cost without weakening checks

**Goal.** Measure and reduce repeated work in pinned CPU LibTorch execution. Wave 23's release source route takes about 6.4 seconds for tiny matrices, while direct C++ takes about 0.103 seconds. Those whole-process observations do not yet attribute the difference.

**Exclusive ownership.** `crates/cgx2-bind/**` and `crates/cgx2-libtorch/**`, including local scripts/tests/evidence. No CLI/compiler, foreign/bridge, bench, root Cargo files, or shared document changes. Preserve public APIs, error categories, and binding/closure lock schemas so the parallel language lane remains independent.

## Deliverable and guardrails

1. First collect reproducible release-profile before measurements and cost attribution on the frozen common commit. Account for preflight, pinned-file hashing, loaded-module census, ELF metadata inspection/subprocesses, and operation boundary checks. Record which phases are measured directly and which remain unmeasured. Do not infer isolated phase costs by subtracting incomparable process runs. Any instrumentation must be opt-in, keep normal output unchanged, and not alter validation order or first failure.
2. Implement a narrowly justified reduction in repeated parsing, allocations, subprocess work, or hashing implementation overhead. Preserve every existing pre-open and before/after-call verification boundary, full pinned content validation, held-file identity, path/loader-environment checks, required closure membership, conflicting SONAME detection, and fail-closed behavior. Immutable per-open metadata reuse is allowed only when its content and identity are still validated at the original boundaries. Metadata-only trust, path-only/global caches, skipped rehashes, disabled validation, batching away checks, or assuming ordinary package files cannot mutate are outside this task. If measurement shows no safe useful optimization, deliver instrumentation plus a precise blocker; do not weaken the contract to obtain a speedup.
3. Retain resistance to replacement by rename, changed same-inode bytes (including same size and restored mtime), deleted/symlinked paths, malicious loader paths, same-name/SONAME substitutions, unexpected mapped Torch/C10 modules, malformed/missing ELF metadata, and stale state after failed opens/calls. Do not retain trusted cached state across independent packages or a failed verification. Preserve original behavior after a later legitimate retry and all tensor cleanup/handle lifetimes. State the existing concurrent mutation threat boundary honestly; do not claim that filesystem polling creates immutable executable memory.
4. Use real pinned CPU Torch 2.11.0 f32 where available, and existing f64 coverage. Build exact same CLI/source/inputs/package/toolchain before/after in release; only this lane's code differs. Preregister at least five independent cold repetitions per version and fixed order/randomization, controls, hashes, tolerance `atol=rtol=1e-5`, and failure policy. Include all failures/timeouts. No p95 with fewer than 20 samples. Report unchanged numeric outputs and exact binary ELF/maps free of Python. Warm direct C facade is a different route and cannot stand in for pinned source measurements.

## Verification and handoff

Run offline bind/LibTorch suites and existing adversarial closure/lifetime fixtures, add regressions for the specific optimization, run CLI mock float64/f32 regressions without editing them, and real f32 before/after where packages exist. Run owned format/Clippy `-D warnings`. Save raw measurements and invocation settings under an owned evidence path, list skips and exclusions, compare counts/cost without an unsupported general speed claim, commit owned changes, and stop. A root lockfile change must be reported to the coordinator, never edited by this lane.
