# Immutable nominal scalar records

**Goal.** Give CGx2 a first useful structured value that is easy for a person and LLM to read, while keeping memory behavior explicit and predictable.

**Ownership.** Edit only `crates/cgx2-syntax/**`, `crates/cgx2-sema/**`, `crates/cgx2-cli/**`, `crates/cgx2-emit-rust/**`, `crates/cgx2-api-index/**`, `crates/cgx2-effect-index/**`, `crates/cgx2-package/**`, `crates/cgx2c/src/**`, `crates/cgx2c/Cargo.toml`, and `crates/cgx2c/tests/record_*`. The memory lane owns `crates/cgx2c/tests/memory_release_*`; do not edit those. Do not edit Python emitter, runtime, foreign, notebook, or root Cargo files.

## Deliverable

1. Accept module-level `record Point:` followed by one to eight four-space-indented named `i64` or canonical `Bool` fields. Construct with `Point(x: 3, y: 4)` and read with `p.x`. Field names are unique and constructor arguments are named exactly once. Evaluate argument expressions left to right in source order, including first error and step-budget behavior, then place values in declaration order. Records are immutable, nominal, copy-by-value scalar aggregates with no hidden managed allocation, destructor, mutation, recursion, nested record field, generic parameter, or foreign layout promise. Keep the formatter's canonical four-space style and stable source spans.
2. Check unknown/duplicate/missing fields, wrong scalar type, unknown record type, invalid field access, use before definition, and unsupported ownership crossings with source-located diagnostics. Reuse `ExprKind::Name(Path)` for `p.x` and `ExprKind::Call` for constructors; do not add expression or statement enum variants that break unowned crates. In semantic resolution, a local record-typed binding followed by one field segment means field access; otherwise preserve qualified module-name resolution. Test both forms in one source and diagnose ambiguity rather than guessing. `let` and pure local function calls may carry record values within one module. Public record use across package module boundaries may be rejected in this slice with an explicit diagnostic; do not silently reinterpret it as a structural type. Existing scalar and tensor profiles must continue to work.
3. Execute records through `cgx2 check/run`, Rust emission and `cgx2c` debug/release output with the same field values, checked arithmetic in field expressions, and deterministic errors. Expose record declarations and field types in the structured API index; preserve prior schema output for modules without records. If the package loader needs an AST compatibility update, keep its existing public API stable.
4. Test nested function calls with a record parameter/result, reordered named arguments, i64 edge values, Bool fields, shadowing, formatter round-trip, diagnostics/spans, and no hidden runtime allocation. Include one source/native package fixture and compare debug/release result and error class. State that variants, generics, lists, mutable records, and record use in Python output remain future work. The coordinator will run full-workspace compatibility tests after integration; report any downstream crate that cannot safely reject records under the current ownership boundary.

## Verification and handoff

Run targeted offline tests for all owned crates, source/native record parity in debug and release, `cargo fmt --all --check`, and owned Clippy `-D warnings`. Commit only owned paths; report SHA, example `.cg`, exact results, and unsupported features. Stop for review.
